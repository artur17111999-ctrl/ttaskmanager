НАСТРОЙКА ПОДКЛЮЧЕНИЯ К POSTGRESQL

Пароли и другие секреты базы данных не хранятся в репозитории.
Приложение принимает следующие переменные окружения:

- STICKY_CRM_DB_HOST: адрес PostgreSQL, по умолчанию localhost;
- STICKY_CRM_DB_PORT: порт, по умолчанию 5432;
- STICKY_CRM_DB_NAME: база, по умолчанию sticky_crm;
- STICKY_CRM_DB_USER: роль приложения, по умолчанию sticky_app;
- STICKY_CRM_DB_PASSWORD: пароль роли; значение не записывать в Git;
- STICKY_CRM_DB_SSLMODE: режим TLS, по умолчанию require;
- STICKY_CRM_DB_SSLROOTCERT: путь к доверенному корневому сертификату.

Для production:

1. Использовать отдельную роль sticky_app без SUPERUSER, CREATEDB, CREATEROLE,
   REPLICATION и BYPASSRLS.
2. Не выдавать desktop-клиенту прямые права на таблицы после перехода на API.
3. Использовать STICKY_CRM_DB_SSLMODE=verify-full и корпоративный CA.
4. Хранить пароль в secret manager или защищённой конфигурации процесса.
5. Для миграций использовать отдельную временно выдаваемую роль, а не sticky_app.
6. После смены пароля перезапустить процессы и отозвать старые подключения.

Для локальной разработки допускается явно установить SSLMODE=disable только для
PostgreSQL на том же компьютере и только при отсутствии реальных данных.

Текущий пароль, ранее находившийся в истории Git, необходимо считать
скомпрометированным: удалить его из текущего файла недостаточно. Требуется сменить
пароль в PostgreSQL, обновить локальный secret и проверить журналы доступа.
